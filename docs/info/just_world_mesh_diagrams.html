piros2 · session anatomy

How just world_mesh works

One recipe, two machines, seven processes (five with odom:=kp), one RViz window whose closing tears everything down. This is the mesh-first fork session — piros2_world_mesh, aliased just dev and just run — with 6-DoF rgbd_odometry by default and the TSDF as the only fusion accumulator (no cloud_mapper; just world keeps the classic session with the voxel panorama). The four diagrams below are four different cuts through the same session: what data flows where, what crosses the Wi-Fi link, how the TF tree is owned, and how the recipe starts and stops it all. Reference tables with the measured numbers — every topic, service, and per-node cost — close the page.
