# Setting up the dev box (Ubuntu 24.04)

The dev box runs ROS 2 Jazzy **natively**. Ubuntu 24.04 (noble) is Jazzy's Tier 1
platform, so this is a plain `apt` install — which matters because `rviz2` and
`rqt` are GUI apps and are far less painful outside a container.

Since the Pi is being reflashed to Ubuntu 24.04 as well
([setup-pi.md](setup-pi.md)), both machines end up with the same install and the
same [Ansible](ansible.md) roles provision both.

## Do it by hand first

The playbook can install all of this in one command, and eventually it should. Work
through it manually the first time anyway. This is a learning project, and a play
that installs ROS while you watch teaches you nothing about what it installed — you
will write a better role afterwards, from what you actually ran.

Once it works here, [ansible.md](ansible.md) is where it gets captured.

## Install ROS 2 Jazzy

```bash
sudo apt update && sudo apt install -y software-properties-common curl
sudo add-apt-repository universe

# The apt source is itself shipped as a .deb that keeps its own signing key current.
export ROS_APT_SOURCE_VERSION=$(
  curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest \
  | grep -F '"tag_name"' | awk -F'"' '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb \
  "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo $VERSION_CODENAME)_all.deb"
sudo apt install -y /tmp/ros2-apt-source.deb

sudo apt update
sudo apt install -y ros-jazzy-desktop
```

`ros-jazzy-desktop` pulls in `rviz2`, `rqt`, the demo nodes, and the standard
message packages. That is what you want here — the Pi gets the much smaller
`ros-jazzy-ros-base` instead, since it is a sensor head with no reason to carry the
Qt stack.

Then the DDS vendor this project standardises on, plus the build tooling:

```bash
sudo apt install -y ros-jazzy-rmw-cyclonedds-cpp
sudo apt install -y python3-colcon-common-extensions python3-rosdep python3-vcstool
sudo rosdep init      # only once per machine; errors harmlessly if repeated
rosdep update         # as your own user, NOT under sudo
```

`rosdep update` writes to `~/.ros`, so running it with `sudo` puts the cache in
root's home where your builds will not find it. The same trap applies in the
Ansible role — see [ansible.md](ansible.md#gotchas-specific-to-provisioning-ros).

## Shell setup

Do **not** blindly source ROS in `.bashrc`. It leaks ROS's Python and library
paths into every shell, which will eventually confuse an unrelated project. Use an
alias instead:

```bash
cat >> ~/.bashrc <<'EOF'

# --- ROS 2 Jazzy ---
alias rosjazzy='source /opt/ros/jazzy/setup.bash && echo "ROS 2 Jazzy sourced (domain $ROS_DOMAIN_ID)"'
export ROS_DOMAIN_ID=42
export ROS_LOCALHOST_ONLY=0
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///home/bthek1/piros2/config/cyclonedds.xml
EOF
```

Those four exports **must match on the Pi**, or the two machines will not see each
other — [networking.md](networking.md) explains each one. That requirement is the
main argument for managing this block from Ansible rather than by hand; the role
writes the same block on both hosts from a single variable definition.

`CYCLONEDDS_URI` points at the interface-pinning config that keeps DDS off this
machine's Docker bridges. Create it before first use —
[networking.md](networking.md#the-docker-bridge-problem-on-the-dev-box).

## Verify

```bash
source /opt/ros/jazzy/setup.bash
ros2 doctor --report | head -30
```

Two-terminal smoke test:

```bash
# terminal 1
ros2 run demo_nodes_cpp talker
# terminal 2
ros2 run demo_nodes_cpp listener
```

If the listener prints incoming messages, the local install is sound. Getting the
same to work *across* the LAN is a separate problem — that is
[networking.md](networking.md).

Then check the GUI tools actually open:

```bash
rviz2
rqt_graph
```

## Workspace layout

The repository is intended to be used as the colcon workspace source directory:

```
~/piros2/
├── src/                 # ROS 2 packages live here
├── ansible/             # provisioning for both machines
├── config/              # cyclonedds.xml, camera calibration
├── docs/
├── build/  install/  log/    # generated by colcon, git-ignored
└── CLAUDE.md  README.md
```

Build and source with:

```bash
cd ~/piros2
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

`--symlink-install` means edits to Python nodes and launch files take effect
without rebuilding — worth having on from the start.
